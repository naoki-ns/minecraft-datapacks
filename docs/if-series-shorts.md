# if シリーズ / ショート動画向けの案

縦・15〜40秒・スクロールを止めることが最優先の回向け。
腰を据えて遊ぶ用の案は `if-series-ideas.md`。当面はこちらを優先する。

---

## 「赤が最強の世界」がなぜ効くのか

構造を分解すると、こう。

```
共通トリガー（触る / 壊す / 殴る / 食べる）
  × 対象ごとに違う反応テーブル（ブロックA→爆発、MobB→巨大化、…）
  = 何が起こるか予想できないので、次のカットまで指が止まる
```

効いているのは「反応が対象ごとに違う」こと。ここが一定だと2カット目で飽きる。
逆にここが豊富なら、**ネタ切れしないまま同じパックで何本も撮れる**し、
コメントに「〇〇でやって」が溜まる＝次の台本が視聴者から降ってくる。

だからショート向けの案は、次の3つを満たすものだけを採る。

1. **ルールがテロップ1行で伝わる**（説明に3秒使ったら負け）
2. **3〜5秒ごとに新しい反応が出る**（1本に4〜6ネタ入る）
3. **反応テーブルを足すだけで次回が撮れる**（実装が1回で済む）

### ショート1本の構成（型）

| 秒 | やること |
| --- | --- |
| 0.0〜0.5 | **異常を先に見せる**。ルール説明より前に1個目の反応を出す |
| 0.5〜2 | テロップでルール1行。「この世界では○○が最強」 |
| 2〜25 | 反応を4〜6連発。**予想どおり3 → 予想外1** の順で置くと落差が出る |
| ラスト2秒 | 次の引き。「じゃあ○○は?」で終わってコメントを取る |

撮影側の都合として、各パックに「反応を即発火させるデバッグコマンド」を
用意しておくこと（撮り直しのたびに条件を揃えるのは無理）。

### 共通エンジンを1つ作る

`if-series-ideas.md` では「共通ライブラリは作らない」と書いたが、**ショート路線では前提が変わる**。
下の案はどれも「トリガーを1つ拾って、対象名で反応テーブルを引いて、対応する関数を呼ぶ」だけ。
ここを1本作れば、2本目以降は**反応テーブルを書くだけ**になる。

```
<ns>:internal/fire   … トリガー発火（対象名が storage に入っている状態で呼ぶ）
  └ マクロで  <ns>:reaction/<対象名>  を呼ぶ（無ければ default）
data/<ns>/function/reaction/*.mcfunction   … 1ファイル1ネタ。ここだけ増やしていく
```

トリガーの取り方（26.3 で使えるはずのもの。実装時に要確認）:

| したいこと | 手段 |
| --- | --- |
| ブロックを壊した | 統計スコアボード `minecraft.mined:<block>` の差分（対象ブロックごとに1つ定義） |
| Mob を殴った / 触った | アドバンスメント `minecraft:player_interacted_with_entity` / `player_hurt_entity` |
| 食べた | アドバンスメント `minecraft:consume_item` |
| ブロックを置いた | `minecraft:placed_block` |
| アイテムを持った | `minecraft:inventory_changed`、または装備スロットの直接判定 |

## 案（ショート適性の高い順）

### 1. もし壊したブロックが復讐に来る世界だったら —「報復」

- **ルール1行**: この世界のブロックは、壊されたら黙っていない
- **反応テーブルの例**
  - 土 → 土ブロックが四方から飛んできて殴られる
  - 石 → その場からアイアンゴーレムが立ち上がる
  - 原木 → 木が殴り返す（ノックバックで吹っ飛ぶ）
  - 砂 → 上から砂に生き埋め
  - 鉄鉱石 → 鉄の装備をした村人が怒って湧く
  - ダイヤ鉱石 → 画面が暗転してからウォーデン
  - ケーキ → 泣く（音とパーティクルだけ。落差担当）
- **なぜショート向き**: 掘るという**誰でも毎回やる行動**が全部オチになる。1本で6回掘れる
- **引きの作り方**: 「次はネザライトを掘ります」で終わる
- **実装**: 統計 `minecraft.mined:*` の差分でトリガー、反応は関数1つずつ。位置はプレイヤー足元で十分
- **難易度 ★2 / 映え ◎◎ / ネタ上限 無限**

### 2. もし土が最強の世界だったら —「価値の逆転」

- **ルール1行**: レア度が逆。土が最強、ダイヤは最弱
- **反応テーブルの例**
  - 土の剣 → 一撃でウォーデンが沈む
  - ダイヤの剣 → ダメージ1、しかもすぐ折れる
  - 土ブロック → TNTが至近で爆発しても無傷
  - ダイヤブロック → 素手で一瞬で割れる
  - フル装備ダイヤ vs 土の防具 → 土側が無傷
  - ネザライト → 手に持つとダメージを受ける（最下層扱い）
- **なぜショート向き**: 全視聴者が持っている「ダイヤは強い」という前提を殴る。0.5秒で異常が伝わる
- **実装**: 攻撃力・防御は属性と装備コンポーネントで作れる。ただし**ブロックの硬さはデータパックでは変えられない**ので、「壊れた瞬間に復元する」演出で代用する。ここだけ試作が必要
- **難易度 ★2 / 映え ◎◎**

### 3. もし名前が長いほど強い世界だったら —「文字数が力」

- **ルール1行**: 攻撃力＝アイテム名の文字数
- **反応テーブルの例**
  - 「エンチャントされた金のリンゴ」（14文字）= 最強の武器
  - 「土」（1文字）= ダメージ1
  - 「ネザライトの剣」より「金のニンジン」が強い
  - 「棒」で殴る → ほぼ効かない
  - 名前を変更（金床でリネーム）すると強くなる → **裏技として成立する**
- **なぜショート向き**: 説明が1行で完結し、結果が数字で即出る。言葉遊びなのでコメントが伸びる（「〇〇なら何文字」）
- **引きの作り方**: 「名前を長くすれば無敵では?」で次回に繋がる（リネーム回）
- **実装**: アイテム名→攻撃力のテーブルと、手に持った物の判定。リネーム対応は名前文字数を数える必要があるので、まずは固定テーブルから
- **難易度 ★1 / 映え ◎◎**

### 4. もし食べ物ごとに違う力が出る世界だったら —「食」

- **ルール1行**: この世界の食べ物は、全部ちがう力になる
- **反応テーブルの例**
  - パン → 空を飛ぶ
  - ニンジン → 目からビーム（視線方向に攻撃）
  - スイカ → 体が巨大化
  - 焼き鳥 → 超スピード
  - 腐肉 → 操作が反転する
  - フグ → 即死（落差担当）
  - ケーキ → 周囲が全部ケーキになる
- **なぜショート向き**: 「全部食べてみた」形式にすると**1本に7ネタ入る**。テンポが最も出しやすい
- **実装**: `minecraft:consume_item` のトリガー1つ＋反応関数。**この路線で一番実装が軽い**のでエンジンの1本目に向く
- **難易度 ★1 / 映え ◎**

### 5. もし撫でるとMobが進化する世界だったら —「進化」

- **ルール1行**: 右クリックで生き物が進化する
- **反応テーブルの例**
  - 豚 → ゾンビピグリン → ピグリン → ピグリンブルート → …
  - ニワトリ → ガスト（羽つながり）
  - 牛 → ムーシュルーム → レッドストーンゴーレム的な何か
  - スライム → マグマキューブ → 巨大スライム
  - 村人 → 村人ゾンビ → エヴォーカー（怖い方向へ）
  - ネコ → オセロット → 巨大化して襲ってくる
- **なぜショート向き**: 連打で**段階的に化けていく**ので、次のカットを見ないと終われない。進化チェーンそのものが引きになる
- **実装**: `player_interacted_with_entity` → Mob 種別で分岐して置換＋パーティクル。段階はスコアで持つ
- **難易度 ★2 / 映え ◎◎**

### 6. もしドロップが64倍の世界だったら —「64倍」

- **ルール1行**: この世界では全部が64倍
- **反応テーブルの例**
  - 牛1匹 → 肉で画面が埋まる
  - 木1本 → 原木が山になって視界が消える
  - ゾンビ1体 → スポーン時に64体
  - TNT1個 → 爆発が64連鎖
  - 小麦1回の収穫 → 画面が黄色く埋まる
- **なぜショート向き**: **画面が物で埋まる映像**は理屈なしでスクロールが止まる。サムネも作りやすい
- **実装**: ルートテーブルの個数倍化（簡単）＋スポーン時複製（負荷注意、上限と半径を config に）
- **難易度 ★2 / 映え ◎◎**（ただしネタの幅は他より狭い。単発向き）

### 7. もし殴るほど武器が進化する世界だったら —「連鎖」

- **ルール1行**: 1体倒すごとに武器が進化する。殴られると退化する
- **反応テーブルの例**: 素手 → 棒 → 木の剣 → 石 → 鉄 → ダイヤ → ネザライト → 雷を落とす剣 → 画面を割る剣
- **なぜショート向き**: 進行が右肩上がりで、**見終わるまでのテンポが自動で作れる**。退化があるので緊張も出る
- **実装**: キル数スコア → 段階ごとに手持ちを差し替え。被弾で1段戻す
- **難易度 ★1 / 映え ◎**

### 8. もしMobが本音を喋る世界だったら —「本音」

- **ルール1行**: 近づくと生き物の本音が聞こえる
- **反応テーブルの例**: クリーパー「ちょっと話したいだけなのに」／ウィザースケルトン「この剣、拾い物」／村人「在庫ないです」／エンダーマン「見るな」／ウォーデン（無言で近づいてくる）
- **なぜショート向き**: 読ませる媒体としてショートは有利。**テキストが面白ければ保存とコメントが伸びる**
- **実装**: 頭上に `text_display`、種別ごとのセリフテーブルからランダム。実装は軽い。**勝負はセリフの質**
- **難易度 ★1〜2 / 映え ○〜◎**

### 9. もし5秒ごとに世界のルールが変わる世界だったら —「ルーレット」

- **ルール1行**: 5秒ごとに世界のルールが変わる
- **反応テーブルの例**: 全員巨大化 / 低重力 / TNTの雨 / 足元が溶岩 / 全ブロックがスライム / 視界反転 / Mob全消滅
- **なぜショート向き**: 「次々に色々起こる」を**最も直接的に**満たす。1本の情報密度が最大
- **戦略上の利点**: 他のifパックで作ったルールを**そのままイベントとして流し込める**。シリーズが進むほど強くなるし、総集編ショートが撮れる
- **実装**: タイマー＋イベントテーブル。個々のイベントは他パックの流用
- **難易度 ★2（個々のイベント次第） / 映え ◎◎**
- **出す順**: これは**最後**。弾が溜まってから出すと一番強い

## 出す順の案（ショート路線）

| 弾 | パック | 理由 |
| --- | --- | --- |
| 1 | **4 食** | エンジン（トリガー→反応テーブル）を一番軽い題材で作る。1本7ネタ入る |
| 2 | **1 報復** | エンジンをブロック破壊トリガーに広げる。ネタ上限が無限で長く使える |
| 3 | **3 文字数が力** | 実装が軽い休憩回。言葉遊びでコメントが伸びる |
| 4 | **5 進化** | Mob トリガーを追加。チェーンで引きが作れる |
| 5 | **2 土が最強** | ブロック復元の試作を挟む必要があるのでここ |
| 6 | **9 ルーレット** | 1〜5の資産を全部流し込む総集編 |

`6 64倍` と `8 本音` は箸休めとして好きなタイミングで挿せる（どちらも★1〜2）。

## 最初にやること

1. `4 食` を作りながら、`internal/fire` → `reaction/<対象>` のエンジンを確定させる
2. 撮影用の即発火コマンド（`<ns>:debug/fire <対象>`）を最初から入れる
3. 反応テーブルの追加手順を README に書く（＝次回の台本が実装作業だけで済む状態にする）
